## 结论先行

**能，但要装一个"中间人"。** 小爱音箱自己读不了 NAS，你必须在一台常年开着的机器（NAS 最合适）上跑一个自托管音乐服务器，它把本地歌曲变成链接，再借小米的协议把播放指令塞给音箱。

**2026 年这条路上唯一还活着的选择是 Songloft**——老牌方案 XiaoMusic 已经在 5 月停止维护了。

再说清楚一件事，免得白折腾：**这套方案播的是你自己已经拥有的音乐文件**（CD 抓轨、购买下载的无损、自己录的音频、给孩子存的故事音频）。它不是"免费听全网付费歌"的口子，凡是涉及下载他人版权内容的做法，本文一律不讲、也不建议。它的价值是**让你已经买过的音乐，能随时用一句话放出来**。

## 先说不适合谁

三个条件有任何一条不满足，就别动手，直接充会员更省心。

**一、手上没有本地音乐文件。** 如果你的曲库 100% 来自在线平台，这条路对你毫无意义。QQ 音乐绿钻连续包年 ¥138、网易云黑胶 VIP ¥158（2026-10-09 核对），一年一百多块换几千万首曲库，比自己攒文件划算得多。

**二、只想"随便放点背景音"。** 手机蓝牙或 AirPlay 连音箱，三秒钟的事，比配 Docker 简单两个数量级。

**三、NAS 不支持 Docker。** 这是硬门槛，比如绿联的 **DH2300 就不支持 Docker**，装不了；DXP2800 / DXP4800 及以上、群晖、威联通的 x86 机型才可以（为什么我一直强调 x86，见[准系统和成品怎么选](/2026/10/nas-barebone-vs-readymade-2026/)）。

## 为什么小爱同学不能直接读 NAS

这是理解整套方案的钥匙，先花两分钟讲清楚。

小爱音箱在系统里是个**播放器**，不是**浏览器**。它不会去读 SMB 共享、不认 NFS，也不认 Subsonic（Navidrome 那套协议）。它能做的只有一件事：接收一条来自小米云的指令，指令里带一个音频 URL，然后播这个 URL。

所以"让音箱播 NAS 里的歌"这个问题，本质上是两个子问题：

1. **怎么让本地文件变成一个音箱能访问的 URL** —— 需要一个音乐服务器
2. **怎么让音箱收到"播这个 URL"的指令** —— 需要能下发指令的通道

**DLNA 为什么不够用？** 网上很多教程说"NAS 开 DLNA，音箱就能播"，这话只对一半。DLNA 能做到的是：你在手机上装个 BubbleUPnP，手动选歌、手动推给音箱。手机必须一直当遥控器，语音点播依然做不到，曲库浏览也在手机 App 里、不在音箱里。体验是割裂的，用两次就会放弃。

真正要做到"小爱同学，播放周杰伦的晴天"，必须有那个中间人。

## 四条路对比（2026-10-09）

| 方案 | 语音点播 | 手机中转 | 维护状态 | 难度 |

| DLNA 推送 | ❌ | 每次都要 | 无需维护 | 低 |
| XiaoMusic | ✅ | 不需要 | **2026-05 已停维护** | 中 |
| **Songloft + MIoT 插件** | ✅ | 不需要 | **活跃（v2.12.0）** | 中 |
| 刷机接管（open-xiaoai） | ✅ | 不需要 | 社区维护 | 高 |

**已经在用 XiaoMusic 的**：别急着升级也别急着拆，把遥测关掉、确认服务没暴露到公网，然后观察 Songloft 的成熟度。

**新装的：直接从 Songloft 开始。** 它是 XiaoMusic 作者预告过的个人音乐服务器的正式形态，v2.0 起改名，Go 重写，Apache-2.0 授权，2026 年 2 月开仓、9 月仍有提交，镜像下载量已过 27 万次。它本身不提供任何音乐内容，曲库全靠你自己放——这正是我们要的合规形态。

有一点要说在前面：Songloft 对小爱音箱的支持不是内置功能，而是通过官方示意插件 `songloft-plugin-miot`，走 MIoT 协议把歌投到音箱。**语音指令的深度整合还在靠社区补**，如果你的机型表现不佳，先去项目讨论区看看同型号的情况，别默认一定能用。

## 部署：三步，绿联 DXP 为例

核心就是一个 Docker 容器，把音乐目录挂进去。

```
services:
  songloft:
    image: songloft-org/songloft
    container_name: songloft
    restart: unless-stopped
    ports:
      - "你选的端口:容器内端口"
    volumes:
      - /volume1/docker/songloft/data:/data
      - /volume1/music:/music:ro     # 只读挂载，保护原始文件
    environment:
      - TZ=Asia/Shanghai
```

**第一步：装。** NAS 的 Docker 应用里新建项目，粘贴上面的配置，把路径换成你自己的。国内拉镜像卡住就去 Docker 设置里加镜像加速源，别硬等。

**第二步：登录小米账号，拉设备列表。** 在 Web 后台填小米账号，保存后它会列出你名下的音箱，勾选要接管的那台。

**第三步：扫描音乐。** 确认音乐目录挂对了，点扫描，之后说一句"小爱同学，播放歌曲"试试。

**⚠️ 安全上两件事必须做**：一是**不要把这个 Web 后台暴露到公网**，真要远程访问就走内网穿透 + 强密码；二是**专门注册一个小米账号给音箱用，别和摄像头用同一个账号**——账号凭据一旦泄露，摄像头是另一个量级的风险。

## 三个必踩的坑

**一、FLAC 不是每台音箱都吃。** 已知 **L05B、L05C、LX06（小爱音箱 Pro）、L16A（Xiaomi Sound）不支持 FLAC**。这几个型号的用户如果放不出声音，在服务端打开「转换为 MP3」和「型号兼容模式」，让 ffmpeg 转一道就行。其余型号 mp3 / flac / wav / ape / ogg / m4a 六种都支持。

**二、IP 地址只填纯 IP，别带端口。** 这是最高频的故障原因：填了 `192.168.1.50:8090` 这种带端口的格式，索引能正常显示歌名，但音频流建立不起来，表现就是"列表有歌、点了没声"。另外给 NAS 配个静态 IP，DHCP 一变地址整套就断。

**三、断网就用不了，NAS 也不能关机。** 指令要经过小米云中转，外网的活儿，所以 NAS 得一直开着——这一点和 NAS 本身的定位倒是契合，它不是为了这个才买，但买了之后正好合适。

**所以坦白讲：如果你的目标是"花最少的钱听最多的歌"，充会员赢，别折腾 NAS。**

NAS 这套方案赢在另外三件事上：

**一是会员解决不了的歌。** 下架的、没有版权的、绝版的现场版，还有孩子听的绘本音频、评书相声、白噪音——这些平台要么没有，要么你得额外买。文件在你手里就是一直在。

**二是边际成本几乎为零。** 一张 FLAC 专辑 300–500MB，一千首大约 30–50GB。一块 4TB 的盘（[硬盘怎么买见这篇](/2026/10/nas-hdd-2026/)）能装几万首，摊到每首歌上的成本可以忽略——**而会员是年年要交的**。

**三是音质自己说了算。** 平台宣传的"母带音质"多数是 AI 升频和算法增强，不是原始母带。你自己抓的 CD 是无损就是无损，没人能悄悄给你换个版本。

一句话总结这笔账：**已有无损库的，边际成本 0，值得做；为了省钱从零开始攒文件的，不划算，直接充会员。**

## 下单前清单

- [ ] 音箱型号确认在支持列表里，且知道它到底吃不吃 FLAC（L05B / L05C / LX06 / L16A 不吃）
- [ ] NAS **支持 Docker**（绿联 DH2300 不支持；DXP 系列、群晖、威联通 x86 可以）

- [ ] Web 后台**不暴露公网**，音箱用专门的小米账号（别和摄像头共用）
- [ ] 曲库来源合规：只放你自己拥有权利的文件
